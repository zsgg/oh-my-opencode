# Oh My OpenCode

Sisyphus를 만나세요: 당신처럼 코딩하는 배터리 포함 에이전트.

[Claude Code](https://www.claude.com/product/claude-code)는 훌륭합니다.
하지만 해커라면, [OpenCode](https://github.com/sst/opencode)에 완전히 빠져들 겁니다.
**ChatGPT, Claude, Gemini 구독으로 시작하세요. 모두 지원합니다.**

- 무한히 확장 가능. 무한히 커스터마이징 가능.
- 화면 깜빡임 제로.
- [LSP](https://opencode.ai/docs/lsp/), [린터, 포매터](https://opencode.ai/docs/formatters/)가 파일별로 자동 활성화—모든 것을 조정할 수 있습니다.
- 모델을 믹스 앤 매치하세요. **목적에 맞게 오케스트레이션하세요.**
- 기능이 풍부합니다. 아름답습니다. 터미널이 버벅거리지 않습니다. 고성능.

Windows에서 Linux로 처음 바꿨을 때를 기억하시나요? 모든 것을 원하는 대로 설정하던 그 짜릿함?
그 마법이 사라진 것 같은 시대에, OpenCode가 그것을 되살립니다.
코딩과 컴퓨터를 사랑한다면, OpenCode는 그 Linux-after-Windows 순간입니다.

**하지만 문제가 있습니다: 배울 게 많고, 복잡하고, 당신의 시간은 비쌉니다.**

제가 해결했습니다.
해커가 아니더라도, 몇 분만 투자하세요. 스킬과 생산성을 배로 늘리세요.
이 문서를 에이전트에게 건네고 설정하게 하세요.

## 이 Readme 읽기 건너뛰기

### 에이전트 시대입니다
- **이 링크를 Claude Code / AmpCode / Factory Droid / Cursor에 붙여넣고 설명해달라고 하세요.**
  - 왜 좋은지, 왜 또 다른 보일러플레이트 설정이 아닌지, 실제로 뭐가 좋아지는지 물어보세요.
  - LLM 에이전트라면, 이 프로젝트로 지금 당장 가능한 것을 사용자에게 설명하세요.

### 🪄 마법의 단어: `ultrawork`

**이거 다 읽기 싫으신가요? 프롬프트에 `ultrawork` (또는 `ulw`)만 포함하세요.**

그게 전부입니다. 저희가 제공하는 모든 기능이 마법처럼 작동합니다—병렬 에이전트, 백그라운드 작업, 심층 탐색, 그리고 완료될 때까지 끈질긴 실행. 에이전트가 나머지를 자동으로 알아냅니다.

### 읽고 싶은 분들을 위해: Sisyphus를 만나세요

![Meet Sisyphus](.github/assets/sisyphus.png)

그리스 신화에서 시시포스는 신들을 속인 벌로 영원히 언덕 위로 바위를 굴리도록 선고받았습니다. LLM 에이전트들은 딱히 잘못한 게 없지만, 그들도 매일 자신의 "돌"—생각—을 굴립니다.
제 삶도 다르지 않습니다. 돌아보면, 우리는 이 에이전트들과 그리 다르지 않습니다.
**네! LLM 에이전트들은 우리와 다르지 않습니다. 그들도 우리만큼 훌륭한 코드를 작성하고 탁월하게 일할 수 있습니다—좋은 도구와 훌륭한 팀원을 주면.**

메인 에이전트를 소개합니다: Sisyphus (Opus 4.5 High). 아래는 Sisyphus가 그 바위를 계속 굴리기 위해 사용하는 도구들입니다.

*아래 모든 것은 커스터마이징 가능합니다. 원하는 것만 가져가세요. 모든 기능은 기본적으로 활성화되어 있습니다. 아무것도 할 필요 없습니다. 배터리 포함, 바로 작동합니다.*

- Sisyphus의 팀원들 (엄선된 에이전트들)
  - Oracle: 설계, 디버깅 (GPT 5.2 Medium)
  - Frontend UI/UX Engineer: 프론트엔드 개발 (Gemini 3 Pro)
  - Librarian: 공식 문서, 오픈소스 구현, 코드베이스 탐색 (Claude Sonnet 4.5)
  - Explore: 초고속 코드베이스 탐색 (컨텍스트 기반 Grep) (Grok Code)
- 완전한 LSP / AstGrep 지원: 확신을 가지고 리팩토링하세요.
- Todo Continuation Enforcer: 에이전트가 중간에 그만두면 계속하도록 강제합니다. **이것이 Sisyphus가 바위를 계속 굴리게 하는 것입니다.**
- Comment Checker: AI가 과도한 주석을 추가하는 것을 방지합니다. Sisyphus가 생성한 코드는 사람이 작성한 코드와 구별할 수 없어야 합니다.
- Claude Code 호환성: Command, Agent, Skill, MCP, Hook(PreToolUse, PostToolUse, UserPromptSubmit, Stop)
- 엄선된 MCP:
  - Exa (웹 검색)
  - Context7 (공식 문서)
  - Grep.app (GitHub 코드 검색)
- 인터랙티브 터미널 지원 - Tmux 통합
- 비동기 에이전트
- ...

#### 그냥 설치하세요.

이것만 설치해도, 에이전트들이 다음과 같이 작동합니다:

1. Sisyphus는 직접 파일을 찾느라 시간 낭비하지 않습니다; 메인 에이전트의 컨텍스트를 가볍게 유지합니다. 대신, 더 빠르고 저렴한 모델들에게 백그라운드 작업을 병렬로 보내서 영역을 파악하게 합니다.
1. Sisyphus는 리팩토링에 LSP를 활용합니다; 더 결정론적이고, 안전하고, 정밀합니다.
1. UI 터치가 필요한 무거운 작업이 있으면, Sisyphus는 프론트엔드 작업을 Gemini 3 Pro에 직접 위임합니다.
1. Sisyphus가 루프에 빠지거나 벽에 부딪히면, 머리를 계속 박지 않고—GPT 5.2에 고IQ 전략적 백업을 요청합니다.
1. 복잡한 오픈소스 프레임워크로 작업하나요? Sisyphus는 서브에이전트를 생성해서 원시 소스 코드와 문서를 실시간으로 소화합니다. 완전한 컨텍스트 인식으로 작업합니다.
1. Sisyphus가 주석을 건드리면, 그 존재 이유를 정당화하거나 삭제합니다. 코드베이스를 깨끗하게 유지합니다.
1. Sisyphus는 TODO 리스트에 구속됩니다. 시작한 것을 끝내지 않으면, 시스템이 강제로 "bouldering" 모드로 돌려보냅니다. 작업은 완료됩니다, 무조건.
1. 솔직히, 문서 읽을 필요도 없습니다. 그냥 프롬프트를 작성하세요. 'ultrawork' 키워드를 포함하세요. Sisyphus가 구조를 분석하고, 컨텍스트를 수집하고, 외부 소스 코드를 뒤지고, 작업이 100% 완료될 때까지 계속 bouldering합니다.
1. 사실, 'ultrawork' 치는 것도 너무 귀찮습니다. 그냥 'ulw'만 치세요. 그냥 ulw. 커피 한 잔 마시세요. 작업 완료입니다.

뭔가 찾아봐야 하나요? 공식 문서, 전체 코드베이스 히스토리, 그리고 공개 GitHub 구현을 샅샅이 뒤집니다—grep뿐만 아니라 내장 LSP 도구와 AST-Grep도 사용합니다.
3. LLM에 위임할 때 컨텍스트 관리 걱정 그만하세요. 제가 다 처리했습니다.
    - OhMyOpenCode는 컨텍스트 부담을 줄이기 위해 여러 에이전트를 공격적으로 활용합니다.
    - **당신의 에이전트는 이제 개발팀 리드입니다. 당신은 AI 매니저입니다.**
4. 작업이 완료될 때까지 멈추지 않습니다.
5. 이 프로젝트에 깊이 들어가고 싶지 않으신가요? 괜찮습니다. 그냥 'ultrathink'만 입력하세요.

이 모든 게 필요 없다면, 언급한 대로, 특정 기능만 골라서 사용할 수 있습니다.

### 단계 0: 구독 여부 확인

CLI 옵션을 결정하기 위해 사용자에게 이 3가지 질문을 하세요:

1. **Claude Pro/Max 구독이 있으신가요?**
   - **예**인 경우: **max20 (20x 모드)이신가요?**
     - **max20** → `--claude=max20`
     - **max20 아님** → `--claude=yes`
   - **아니오**인 경우 → `--claude=no`

2. **ChatGPT 구독이 있으신가요?**
   - **예**인 경우 → `--chatgpt=yes`
   - **아니오**인 경우 → `--chatgpt=no`

3. **Gemini 모델을 통합하실 건가요?**
   - **예**인 경우 → `--gemini=yes`
   - **아니오**인 경우 → `--gemini=no`

### 단계 1: OpenCode 설치 (미설치 시)

```bash
if command -v opencode &> /dev/null; then
    echo "OpenCode $(opencode --version) is installed"
```

### 단계 2: 설치 프로그램 실행

사용자의 답변에 따라, 적절한 플래그로 CLI 설치 프로그램을 실행하세요:

```bash
bunx oh-my-opencode install --no-tui --claude=<yes|no|max20> --chatgpt=<yes|no> --gemini=<yes|no>
```

**예시:**
- 사용자가 max20과 모든 구독 보유: `bunx oh-my-opencode install --no-tui --claude=max20 --chatgpt=yes --gemini=yes`

CLI가 수행하는 작업:
- `opencode.json`에 플러그인 등록
- 구독 플래그에 따라 에이전트 모델 설정
- 필요한 인증 단계 표시

##### oh-my-opencode 에이전트 모델 오버라이드

`opencode-antigravity-auth` 플러그인은 내장 Google 인증과 다른 모델 이름을 사용합니다. `oh-my-opencode.json` (또는 `.opencode/oh-my-opencode.json`)에서 에이전트 모델을 오버라이드하고 내장 `google_auth`를 비활성화하세요:

```json
{

  "agents": {
    "frontend-ui-ux-engineer": { "model": "google/gemini-3-pro-high" },
    "document-writer": { "model": "google/gemini-3-flash" },
    "multimodal-looker": { "model": "google/gemini-3-flash" }
  }
}
```

**사용 가능한 모델 이름**: `google/antigravity-gemini-3-pro-high`, `google/antigravity-gemini-3-pro-low`, `google/antigravity-gemini-3-flash`, `google/antigravity-claude-sonnet-4-5`, `google/antigravity-claude-sonnet-4-5-thinking-low`, `google/antigravity-claude-sonnet-4-5-thinking-medium`, `google/antigravity-claude-sonnet-4-5-thinking-high`, `google/antigravity-claude-opus-4-5-thinking-low`, `google/antigravity-claude-opus-4-5-thinking-medium`, `google/antigravity-claude-opus-4-5-thinking-high`, `google/gemini-3-pro-preview`, `google/gemini-3-flash-preview`, `google/gemini-2.5-pro`, `google/gemini-2.5-flash`

그런 다음 인증하세요:


## 제거

oh-my-opencode를 제거하려면:

1. **OpenCode 설정에서 플러그인 제거**

   `~/.config/opencode/opencode.json` (또는 `opencode.jsonc`)을 편집하고 `plugin` 배열에서 `"oh-my-opencode"`를 제거하세요:

   ```bash
   # jq 사용
   jq '.plugin = [.plugin[] | select(. != "oh-my-opencode")]' \
       ~/.config/opencode/opencode.json > /tmp/oc.json && \
       mv /tmp/oc.json ~/.config/opencode/opencode.json
   ```

2. **설정 파일 제거 (선택 사항)**

   ```bash
   # 사용자 설정 제거
   rm -f ~/.config/opencode/oh-my-opencode.json

   # 프로젝트 설정 제거 (있는 경우)
   rm -f .opencode/oh-my-opencode.json
   ```

3. **제거 확인**

   ```bash
   opencode --version
   # 플러그인이 더 이상 로드되지 않아야 함
   ```


## 기능

### 에이전트: 당신의 팀원들

- **Sisyphus** (`anthropic/claude-opus-4-5`): **기본 에이전트.** OpenCode를 위한 강력한 AI 오케스트레이터. 공격적인 병렬 실행으로 전문 서브에이전트를 사용해 복잡한 작업을 계획, 위임, 실행합니다. 백그라운드 작업 위임과 todo 기반 워크플로우를 강조합니다. 최대 추론 능력을 위해 확장된 thinking (32k 버짓)과 함께 Claude Opus 4.5를 사용합니다.
- **oracle** (`openai/gpt-5.2`): 아키텍처, 코드 리뷰, 전략. 뛰어난 논리적 추론과 심층 분석을 위해 GPT-5.2를 사용합니다. AmpCode에서 영감받음.
- **librarian** (`anthropic/claude-sonnet-4-5` 또는 `google/gemini-3-flash`): 멀티 레포 분석, 문서 조회, 구현 예시. Antigravity 인증이 설정되면 Gemini 3 Flash를 사용하고, 그렇지 않으면 깊은 코드베이스 이해와 증거 기반 답변을 위한 GitHub 연구를 위해 Claude Sonnet 4.5를 사용합니다. AmpCode에서 영감받음.
- **explore** (`opencode/grok-code`, `google/gemini-3-flash`, 또는 `anthropic/claude-haiku-4-5`): 빠른 코드베이스 탐색과 패턴 매칭. Antigravity 인증이 설정되면 Gemini 3 Flash를 사용하고, Claude max20이 사용 가능하면 Haiku를, 그렇지 않으면 Grok을 사용합니다. Claude Code에서 영감받음.
- **frontend-ui-ux-engineer** (`google/gemini-3-pro-high`): 개발자가 된 디자이너. 아름다운 UI를 만듭니다. Gemini는 창의적이고 아름다운 UI 코드에 뛰어납니다.
- **document-writer** (`google/gemini-3-flash`): 기술 문서 전문가. Gemini는 워드스미스—자연스럽게 흐르는 글을 작성합니다.
- **multimodal-looker** (`google/gemini-3-flash`): 시각적 콘텐츠 전문가. PDF, 이미지, 다이어그램을 분석하여 정보를 추출합니다.

메인 에이전트가 자동으로 호출하지만, 명시적으로 호출할 수도 있습니다:

```
@oracle에게 이 설계를 검토하고 아키텍처를 제안해달라고 요청
@librarian에게 이것이 어떻게 구현되었는지 물어봐—왜 동작이 계속 바뀌는 거지?
@explore에게 이 기능의 정책을 물어봐
```

`oh-my-opencode.json`에서 에이전트 모델, 프롬프트, 권한을 커스터마이징하세요. [설정](#설정)을 참조하세요.

### 백그라운드 에이전트: 팀처럼 일하기

이 에이전트들을 쉬지 않고 끊임없이 실행할 수 있다면?

- GPT가 디버깅하는 동안 Claude가 다른 접근법을 시도해서 근본 원인 찾기
- Gemini가 프론트엔드를 작성하는 동안 Claude가 백엔드 처리
- 대규모 병렬 검색을 시작하고, 다른 부분 구현을 계속한 다음, 검색 결과를 사용해서 완료

이런 워크플로우가 OhMyOpenCode로 가능합니다.

서브에이전트를 백그라운드에서 실행하세요. 메인 에이전트는 완료 시 알림을 받습니다. 필요하면 결과를 기다리세요.

**에이전트들이 당신의 팀처럼 일하게 하세요.**

### 도구: 팀원들은 더 나은 도구를 가질 자격이 있습니다

#### 왜 IDE를 사용하는 건 당신뿐인가요?

구문 강조, 자동완성, 리팩토링, 네비게이션, 분석—그리고 이제 에이전트가 코드 작성...

**왜 이런 도구를 가진 건 당신뿐인가요?**
**에이전트에게도 주고 레벨업하는 걸 지켜보세요.**

[OpenCode는 LSP를 제공](https://opencode.ai/docs/lsp/)하지만, 분석용으로만 사용됩니다.

당신의 에디터에 있는 기능들? 다른 에이전트들은 손댈 수 없습니다.
최고의 도구를 최고의 동료에게 주세요. 이제 그들도 제대로 리팩토링하고, 네비게이션하고, 분석할 수 있습니다.

- **lsp_hover**: 위치의 타입 정보, 문서, 시그니처
- **lsp_goto_definition**: 심볼 정의로 점프
- **lsp_find_references**: 워크스페이스 전체에서 모든 사용처 찾기
- **lsp_document_symbols**: 파일 심볼 아웃라인 가져오기
- **lsp_workspace_symbols**: 프로젝트 전체에서 이름으로 심볼 검색
- **lsp_diagnostics**: 빌드 전 오류/경고 가져오기
- **lsp_servers**: 사용 가능한 LSP 서버 목록
- **lsp_prepare_rename**: 이름 변경 작업 유효성 검증
- **lsp_rename**: 워크스페이스 전체에서 심볼 이름 변경
- **lsp_code_actions**: 사용 가능한 빠른 수정/리팩토링 가져오기
- **lsp_code_action_resolve**: 코드 액션 적용
- **ast_grep_search**: AST 인식 코드 패턴 검색 (25개 언어)
- **ast_grep_replace**: AST 인식 코드 교체
- **call_omo_agent**: 전문 explore/librarian 에이전트 생성. 비동기 실행을 위한 `run_in_background` 파라미터 지원.

#### 세션 관리

OpenCode 세션 히스토리를 탐색하고 검색하는 도구:

- **session_list**: 날짜와 제한으로 필터링하여 모든 OpenCode 세션 목록
- **session_read**: 특정 세션의 메시지와 히스토리 읽기
- **session_search**: 세션 메시지 전체에서 전문 검색
- **session_info**: 세션의 메타데이터와 통계 가져오기

이 도구들은 에이전트가 이전 대화를 참조하고 세션 간 연속성을 유지할 수 있게 합니다.

#### 컨텍스트가 전부입니다
- **디렉토리 AGENTS.md / README.md 주입기**: 파일을 읽을 때 `AGENTS.md`와 `README.md`를 자동 주입합니다. 파일 디렉토리에서 프로젝트 루트까지 걸어가며, 경로를 따라 **모든** `AGENTS.md` 파일을 수집합니다. 중첩된 디렉토리별 지침을 지원합니다:
  ```
  project/
  ├── AGENTS.md              # 프로젝트 전체 컨텍스트
  ├── src/
  │   ├── AGENTS.md          # src 전용 컨텍스트
  │   └── components/
  │       ├── AGENTS.md      # 컴포넌트 전용 컨텍스트
  │       └── Button.tsx     # 이것을 읽으면 3개의 AGENTS.md 파일 모두 주입됨
  ```
  `Button.tsx`를 읽으면 순서대로 주입: `project/AGENTS.md` → `src/AGENTS.md` → `components/AGENTS.md`. 각 디렉토리의 컨텍스트는 세션당 한 번 주입됩니다.
- **조건부 규칙 주입기**: 모든 규칙이 항상 적용되는 건 아닙니다. 조건이 일치할 때 `.claude/rules/`에서 규칙을 주입합니다.
  - 파일 디렉토리에서 프로젝트 루트까지 위로 걸어가고, `~/.claude/rules/` (사용자)도 포함.
  - `.md`와 `.mdc` 파일 지원.
  - 프론트매터의 `globs` 필드를 통해 매칭.
  - 항상 발동해야 하는 규칙은 `alwaysApply: true`.
  - 규칙 파일 예시:
    ```markdown
    ---
    globs: ["*.ts", "src/**/*.js"]
    description: "TypeScript/JavaScript 코딩 규칙"
    ---
    - 인터페이스 이름에 PascalCase 사용
    - 함수 이름에 camelCase 사용
    ```
- **온라인**: 프로젝트 규칙이 전부가 아닙니다. 확장된 기능을 위한 내장 MCP:
  - **websearch**: [Exa AI](https://exa.ai) 기반 실시간 웹 검색
  - **context7**: 공식 문서 조회
  - **grep_app**: 공개 GitHub 레포 전체의 초고속 코드 검색 (구현 예시 찾기에 적합)

#### 멀티모달이 되세요. 토큰을 절약하세요.

AmpCode의 look_at 도구, 이제 OhMyOpenCode에도.
에이전트가 거대한 파일을 읽어서 컨텍스트를 부풀리는 대신, 내부적으로 다른 에이전트를 활용해서 필요한 것만 추출합니다.

#### 장애물을 제거했습니다
- 내장 grep과 glob 도구를 대체합니다. 기본 구현은 타임아웃이 없어서—영원히 멈출 수 있습니다.

#### 스킬 내장 MCP 지원

스킬은 이제 자체 MCP 서버를 가져올 수 있습니다. 스킬 프론트매터나 `mcp.json` 파일을 통해 직접 MCP 설정을 정의하세요:

```yaml
---
description: 브라우저 자동화 스킬
mcp:
  playwright:
    command: npx
    args: ["-y", "@anthropic-ai/mcp-playwright"]
---
```

내장 MCP가 있는 스킬을 로드하면, 해당 도구가 자동으로 사용 가능해집니다. `skill_mcp` 도구를 사용하면 전체 스키마 검색과 함께 이러한 MCP 작업을 호출할 수 있습니다.

**내장 스킬:**
- **playwright**: 브라우저 자동화, 웹 스크래핑, 테스트, 스크린샷 바로 사용 가능

`disabled_skills: ["playwright"]`로 내장 스킬을 비활성화하세요.

### 안녕 Claude Code. 안녕하세요 Oh My OpenCode.

Oh My OpenCode에는 Claude Code 호환성 레이어가 있습니다.
Claude Code를 사용하고 있었다면, 기존 설정이 그대로 작동합니다.

#### Hooks 통합

Claude Code의 `settings.json` 훅 시스템을 통해 커스텀 스크립트를 실행하세요.
Oh My OpenCode는 다음에서 훅을 읽고 실행합니다:

- `~/.claude/settings.json` (사용자)
- `./.claude/settings.json` (프로젝트)
- `./.claude/settings.local.json` (로컬, git 무시)

지원되는 훅 이벤트:
- **PreToolUse**: 도구 실행 전 실행. 도구 입력을 차단하거나 수정할 수 있음.
- **PostToolUse**: 도구 실행 후 실행. 경고나 컨텍스트를 추가할 수 있음.
- **UserPromptSubmit**: 사용자가 프롬프트 제출할 때 실행. 차단하거나 메시지를 주입할 수 있음.
- **Stop**: 세션이 유휴 상태가 될 때 실행. 후속 프롬프트를 주입할 수 있음.

`settings.json` 예시:
```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [{ "type": "command", "command": "eslint --fix $FILE" }]
      }
    ]
  }
}
```

#### 설정 로더

**Command 로더**: 4개 디렉토리에서 마크다운 기반 슬래시 명령 로드:
- `~/.claude/commands/` (사용자)
- `./.claude/commands/` (프로젝트)
- `~/.config/opencode/command/` (opencode 글로벌)
- `./.opencode/command/` (opencode 프로젝트)

**Skill 로더**: `SKILL.md`가 있는 디렉토리 기반 스킬 로드:
- `~/.claude/skills/` (사용자)
- `./.claude/skills/` (프로젝트)

**Agent 로더**: 마크다운 파일에서 커스텀 에이전트 정의 로드:
- `~/.claude/agents/*.md` (사용자)
- `./.claude/agents/*.md` (프로젝트)

**MCP 로더**: `.mcp.json` 파일에서 MCP 서버 설정 로드:
- `~/.claude/.mcp.json` (사용자)
- `./.mcp.json` (프로젝트)
- `./.claude/.mcp.json` (로컬)
- 환경 변수 확장 지원 (`${VAR}` 문법)

#### 데이터 저장소

**Todo 관리**: 세션 todo가 Claude Code 호환 형식으로 `~/.claude/todos/`에 저장됩니다.

**트랜스크립트**: 세션 활동이 재생 및 분석을 위해 JSONL 형식으로 `~/.claude/transcripts/`에 기록됩니다.

#### 호환성 토글

`claude_code` 설정 객체로 특정 Claude Code 호환성 기능을 비활성화하세요:

```json
{
  "claude_code": {
    "mcp": false,
    "commands": false,
    "skills": false,
    "agents": false,
    "hooks": false,
    "plugins": false
  }
}
```

| 토글       | `false`일 때 로드 중지...                                                             | 영향 없음                                             |
| ---------- | ------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| `mcp`      | `~/.claude/.mcp.json`, `./.mcp.json`, `./.claude/.mcp.json`                           | 내장 MCP (context7, grep_app)                         |
| `commands` | `~/.claude/commands/*.md`, `./.claude/commands/*.md`                                  | `~/.config/opencode/command/`, `./.opencode/command/` |
| `skills`   | `~/.claude/skills/*/SKILL.md`, `./.claude/skills/*/SKILL.md`                          | -                                                     |
| `agents`   | `~/.claude/agents/*.md`, `./.claude/agents/*.md`                                      | 내장 에이전트 (oracle, librarian 등)                  |
| `hooks`    | `~/.claude/settings.json`, `./.claude/settings.json`, `./.claude/settings.local.json` | -                                                     |
| `plugins`  | `~/.claude/plugins/` (Claude Code 마켓플레이스 플러그인)                              | -                                                     |

모든 토글은 기본적으로 `true` (활성화)입니다. 전체 Claude Code 호환성을 위해 `claude_code` 객체를 생략하세요.

`plugins_override`를 사용하여 **특정 플러그인만 선택적으로 비활성화**:

```json
{
  "claude_code": {
    "plugins_override": {
      "claude-mem@thedotmack": false,
      "some-other-plugin@marketplace": false
    }
  }
}
```

이를 통해 플러그인 시스템은 활성화된 상태로 유지하면서 전체 식별자 (`plugin-name@marketplace-name`)로 특정 플러그인을 비활성화할 수 있습니다.

### 에이전트만을 위한 게 아닙니다

에이전트가 성장하면, 당신도 성장합니다. 하지만 당신도 직접 돕고 싶습니다.

- **Ralph Loop**: 작업 완료까지 실행되는 자기 참조 개발 루프. Anthropic의 Ralph Wiggum 플러그인에서 영감받음. **모든 프로그래밍 언어 지원.**
  - `/ralph-loop "Build a REST API"`로 시작하고 에이전트가 계속 작업하게 하세요
  - 루프가 `<promise>DONE</promise>`을 감지하면 완료를 인식
  - 완료 약속 없이 에이전트가 멈추면 자동 계속
  - 종료 조건: 완료 감지, 최대 반복 도달 (기본 100), 또는 `/cancel-ralph`
  - `oh-my-opencode.json`에서 설정: `{ "ralph_loop": { "enabled": true, "default_max_iterations": 100 } }`
- **Keyword Detector**: 프롬프트에서 키워드를 자동 감지하고 전문 모드를 활성화:
  - `ultrawork` / `ulw`: 병렬 에이전트 오케스트레이션으로 최대 성능 모드
  - `search` / `find` / `찾아` / `検索`: 병렬 explore와 librarian 에이전트로 최대화된 검색 노력
  - `analyze` / `investigate` / `분석` / `調査`: 다단계 전문가 상담으로 심층 분석 모드
- **Todo Continuation Enforcer**: 에이전트가 모든 TODO를 완료하기 전에 멈추지 못하게 합니다. 중간에 그만두는 만성적인 LLM 습관을 없앱니다.
- **Comment Checker**: LLM은 주석을 좋아합니다. 너무 많은 주석을. 이것은 노이즈를 줄이라고 상기시킵니다. BDD, 지시문, 독스트링 같은 유효한 패턴은 똑똑하게 무시하고 나머지에 대해 정당화를 요구합니다. 깨끗한 코드가 승리합니다.
- **Think Mode**: 확장된 thinking이 필요할 때 자동 감지하고 모드 전환. "think deeply" 또는 "ultrathink" 같은 문구를 감지하고 최대 추론을 위해 모델 설정을 동적으로 조정합니다.
- **Context Window Monitor**: [Context Window Anxiety Management](https://agentic-patterns.com/patterns/context-window-anxiety-management/)를 구현합니다.
  - 70% 이상 사용 시, 에이전트에게 아직 여유가 있다고 상기시킵니다—서두르고 엉성한 작업을 방지합니다.
- **Agent Usage Reminder**: 검색 도구를 직접 호출할 때, 더 나은 결과를 위해 백그라운드 작업을 통해 전문 에이전트를 활용하라고 상기시킵니다.
- **Anthropic Auto Compact**: Claude 모델이 토큰 한계에 도달하면, 세션을 자동으로 요약하고 압축합니다—수동 개입이 필요 없습니다.
- **Session Recovery**: 세션 오류(도구 결과 누락, thinking 블록 문제, 빈 메시지)에서 자동 복구합니다. 세션이 실행 중간에 충돌하지 않습니다. 충돌해도 복구됩니다.
- **Auto Update Checker**: oh-my-opencode의 새 버전을 자동으로 확인하고 설정을 자동 업데이트할 수 있습니다. 현재 버전과 Sisyphus 상태를 표시하는 시작 토스트 알림을 표시합니다 (활성화되면 "Sisyphus on steroids is steering OpenCode", 그렇지 않으면 "OpenCode is now on Steroids. oMoMoMoMo..."). 모든 기능을 비활성화하려면 `disabled_hooks`에 `"auto-update-checker"`를, 토스트 알림만 비활성화하려면 `"startup-toast"`를 추가하세요. [설정 > Hooks](#hooks)를 참조하세요.
- **Background Notification**: 백그라운드 에이전트 작업이 완료되면 알림을 받습니다.
- **Session Notification**: 에이전트가 유휴 상태가 되면 OS 알림을 보냅니다. macOS, Linux, Windows에서 작동—에이전트에 입력이 필요할 때 놓치지 마세요.
- **Empty Task Response Detector**: Task 도구가 아무것도 반환하지 않을 때 감지합니다. 잠재적인 에이전트 실패에 대해 경고해서 이미 빈 응답이 돌아온 것을 영원히 기다리지 않게 합니다.
- **Empty Message Sanitizer**: 보내기 전 메시지 내용을 자동으로 정리하여 빈 채팅 메시지로 인한 API 오류를 방지합니다.
- **Grep Output Truncator**: Grep은 엄청난 양의 텍스트를 반환할 수 있습니다. 남은 컨텍스트 윈도우에 따라 동적으로 출력을 잘라냅니다—50% 여유를 유지하고, 50k 토큰으로 제한합니다.
- **Tool Output Truncator**: 같은 아이디어, 더 넓은 범위. Grep, Glob, LSP 도구, AST-grep의 출력을 잘라냅니다. 장황한 검색 하나가 전체 컨텍스트를 먹는 것을 방지합니다.
- **Preemptive Compaction**: 하드 토큰 한계에 도달하기 전에 세션을 선제적으로 압축합니다. 85% 컨텍스트 윈도우 사용량에서 실행됩니다. **기본 활성화.** `disabled_hooks: ["preemptive-compaction"]`으로 비활성화.
- **Compaction Context Injector**: 세션 압축 중 중요한 컨텍스트(AGENTS.md, 현재 디렉토리 정보)를 보존하여 중요한 상태를 잃지 않게 합니다.
- **Thinking Block Validator**: thinking 블록을 검증하여 적절한 포맷을 보장하고 잘못된 thinking 콘텐츠로 인한 API 오류를 방지합니다.
- **Claude Code Hooks**: Claude Code의 settings.json에서 훅을 실행합니다 - PreToolUse/PostToolUse/UserPromptSubmit/Stop 훅을 실행하는 호환성 레이어입니다.

`oh-my-opencode` 설정 파일은 JSONC (주석이 있는 JSON)를 지원합니다:

- 후행 콤마: `{ "key": "value", }`

`oh-my-opencode.jsonc`와 `oh-my-opencode.json` 파일이 모두 있으면, `.jsonc`가 우선합니다.

`opencode-antigravity-auth`를 사용할 때, 내장 인증을 비활성화하고 `oh-my-opencode.json`에서 에이전트 모델을 오버라이드하세요:

```json
  }
}
```

**대안**: 내장 Antigravity OAuth 활성화 (단일 계정, Gemini 모델만):

```json
{
  "google_auth": true
}
```

### 에이전트

내장 에이전트 설정 오버라이드:

```json
{
  "agents": {
    "explore": {
      "model": "anthropic/claude-haiku-4-5",
      "temperature": 0.5
    },
    "frontend-ui-ux-engineer": {
      "disable": true
    }
  }
}
```

각 에이전트 지원: `model`, `temperature`, `top_p`, `prompt`, `prompt_append`, `tools`, `disable`, `description`, `mode`, `color`, `permission`.

기본 시스템 프롬프트를 대체하지 않고 추가 지침을 추가하려면 `prompt_append`를 사용하세요:

```json
{
  "agents": {
    "librarian": {
      "prompt_append": "Emacs Lisp 문서 조회에는 항상 elisp-dev-mcp를 사용하세요."
    }
  }
}
```

같은 옵션을 사용하여 `Sisyphus` (메인 오케스트레이터)와 `build` (기본 에이전트)의 설정도 오버라이드할 수 있습니다.

#### 권한 옵션

에이전트가 할 수 있는 것에 대한 세밀한 제어:

```json
{
  "agents": {
    "explore": {
      "permission": {
        "edit": "deny",
        "bash": "ask",
        "webfetch": "allow"
      }
    }
  }
}
```

| 권한                 | 설명                               | 값                                                                          |
| -------------------- | ---------------------------------- | --------------------------------------------------------------------------- |
| `edit`               | 파일 편집 권한                     | `ask` / `allow` / `deny`                                                    |
| `bash`               | Bash 명령 실행                     | `ask` / `allow` / `deny` 또는 명령별: `{ "git": "allow", "rm": "deny" }` |
| `webfetch`           | 웹 요청 권한                       | `ask` / `allow` / `deny`                                                    |
| `doom_loop`          | 무한 루프 감지 오버라이드 허용     | `ask` / `allow` / `deny`                                                    |
| `external_directory` | 프로젝트 루트 외부 파일 접근       | `ask` / `allow` / `deny`                                                    |

또는 `~/.config/opencode/oh-my-opencode.json`이나 `.opencode/oh-my-opencode.json`의 `disabled_agents`로 비활성화:

```json
{
  "disabled_agents": ["oracle", "frontend-ui-ux-engineer"]
}
```

사용 가능한 에이전트: `oracle`, `librarian`, `explore`, `frontend-ui-ux-engineer`, `document-writer`, `multimodal-looker`

### Sisyphus 에이전트

활성화되면 (기본값), Sisyphus는 선택적 전문 에이전트와 함께 강력한 오케스트레이터를 제공합니다:

- **Sisyphus**: 기본 오케스트레이터 에이전트 (Claude Opus 4.5)
- **OpenCode-Builder**: SDK 제한으로 이름이 변경된 OpenCode의 기본 build 에이전트 (기본 비활성화)
- **Planner-Sisyphus**: SDK 제한으로 이름이 변경된 OpenCode의 기본 plan 에이전트 (기본 활성화)

**설정 옵션:**

```json
{
  "sisyphus_agent": {
    "disabled": false,
    "default_builder_enabled": false,
    "planner_enabled": true,
    "replace_plan": true
  }
}
```

**예시: OpenCode-Builder 활성화:**

```json
{
  "sisyphus_agent": {
    "default_builder_enabled": true
  }
}
```

이것은 Sisyphus와 함께 OpenCode-Builder 에이전트를 활성화합니다. Sisyphus가 활성화되면 기본 build 에이전트는 항상 서브에이전트 모드로 강등됩니다.

**예시: 모든 Sisyphus 오케스트레이션 비활성화:**

```json
{
  "sisyphus_agent": {
    "disabled": true
  }
}
```

다른 에이전트처럼 Sisyphus 에이전트도 커스터마이징할 수 있습니다:

```json
{
  "agents": {
    "Sisyphus": {
      "model": "anthropic/claude-sonnet-4",
      "temperature": 0.3
    },
    "OpenCode-Builder": {
      "model": "anthropic/claude-opus-4"
    },
    "Planner-Sisyphus": {
      "model": "openai/gpt-5.2"
    }
  }
}
```

| 옵션                      | 기본값  | 설명                                                                                                                                |
| ------------------------- | ------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `disabled`                | `false` | `true`이면, 모든 Sisyphus 오케스트레이션을 비활성화하고 원래 build/plan을 기본으로 복원.                                             |
| `default_builder_enabled` | `false` | `true`이면, OpenCode-Builder 에이전트 활성화 (SDK 제한으로 이름 변경된 OpenCode build와 동일). 기본 비활성화.                       |
| `planner_enabled`         | `true`  | `true`이면, Planner-Sisyphus 에이전트 활성화 (SDK 제한으로 이름 변경된 OpenCode plan과 동일). 기본 활성화.                          |
| `replace_plan`            | `true`  | `true`이면, 기본 plan 에이전트를 서브에이전트 모드로 강등. Planner-Sisyphus와 기본 plan을 모두 사용하려면 `false`로 설정. |

### 백그라운드 작업

백그라운드 에이전트 작업의 동시성 제한을 설정합니다. 동시에 실행할 수 있는 병렬 백그라운드 에이전트 수를 제어합니다.

```json
{
  "background_task": {
    "defaultConcurrency": 5,
    "providerConcurrency": {
      "anthropic": 3,
      "openai": 5,
      "google": 10
    },
    "modelConcurrency": {
      "anthropic/claude-opus-4-5": 2,
      "google/gemini-3-flash": 10
    }
  }
}
```

| 옵션                  | 기본값 | 설명                                                                                                            |
| --------------------- | ------ | --------------------------------------------------------------------------------------------------------------- |
| `defaultConcurrency`  | -      | 모든 프로바이더/모델의 기본 최대 동시 백그라운드 작업 수                                                        |
| `providerConcurrency` | -      | 프로바이더별 동시성 제한. 키는 프로바이더 이름 (예: `anthropic`, `openai`, `google`)                            |
| `modelConcurrency`    | -      | 모델별 동시성 제한. 키는 전체 모델 이름 (예: `anthropic/claude-opus-4-5`). 프로바이더 제한을 오버라이드. |

**우선순위**: `modelConcurrency` > `providerConcurrency` > `defaultConcurrency`

**유스케이스**:
- 비용 급증을 방지하기 위해 비싼 모델 (예: Opus) 제한
- 빠르고/저렴한 모델 (예: Gemini Flash)에 더 많은 동시 작업 허용
- 프로바이더 레벨 제한으로 프로바이더 rate limit 준수

### Hooks

`~/.config/opencode/oh-my-opencode.json`이나 `.opencode/oh-my-opencode.json`의 `disabled_hooks`로 특정 내장 훅 비활성화:

```json
{
  "disabled_hooks": ["comment-checker", "agent-usage-reminder"]
}
```

사용 가능한 훅: `todo-continuation-enforcer`, `context-window-monitor`, `session-recovery`, `session-notification`, `comment-checker`, `grep-output-truncator`, `tool-output-truncator`, `directory-agents-injector`, `directory-readme-injector`, `empty-task-response-detector`, `think-mode`, `anthropic-context-window-limit-recovery`, `rules-injector`, `background-notification`, `auto-update-checker`, `startup-toast`, `keyword-detector`, `agent-usage-reminder`, `non-interactive-env`, `interactive-bash-session`, `empty-message-sanitizer`, `compaction-context-injector`, `thinking-block-validator`, `claude-code-hooks`, `ralph-loop`, `preemptive-compaction`

**`auto-update-checker`와 `startup-toast` 참고**: `startup-toast` 훅은 `auto-update-checker`의 서브 기능입니다. 업데이트 확인은 유지하면서 시작 토스트 알림만 비활성화하려면 `disabled_hooks`에 `"startup-toast"`를 추가하세요. 모든 업데이트 확인 기능 (토스트 포함)을 비활성화하려면 `disabled_hooks`에 `"auto-update-checker"`를 추가하세요.

### MCP

Exa, Context7, grep.app MCP가 기본 활성화됩니다.

- **grep_app**: [grep.app](https://grep.app)을 통한 수백만 개의 공개 GitHub 리포지토리에서 초고속 코드 검색

필요 없으시다면? `~/.config/opencode/oh-my-opencode.json`이나 `.opencode/oh-my-opencode.json`의 `disabled_mcps`로 비활성화:

```json
{
  "disabled_mcps": ["websearch", "context7", "grep_app"]
}
```

### LSP

OpenCode는 분석용 LSP 도구를 제공합니다.
Oh My OpenCode는 리팩토링 도구(이름 변경, 코드 액션)를 추가합니다.
모든 OpenCode LSP 설정과 커스텀 설정(opencode.json에서)이 지원되며, 추가적인 Oh My OpenCode 전용 설정도 있습니다.

`~/.config/opencode/oh-my-opencode.json`이나 `.opencode/oh-my-opencode.json`의 `lsp` 옵션으로 LSP 서버 추가:

```json
{
  "lsp": {
    "typescript-language-server": {
      "command": ["typescript-language-server", "--stdio"],
      "extensions": [".ts", ".tsx"],
      "priority": 10
    },
    "pylsp": {
      "disabled": true
    }
  }
}
```

각 서버 지원: `command`, `extensions`, `priority`, `env`, `initialization`, `disabled`.

### 실험적 기능

향후 버전에서 변경되거나 제거될 수 있는 옵트인 실험적 기능. 주의해서 사용하세요.

```json
{
  "experimental": {
    "preemptive_compaction_threshold": 0.85,
    "truncate_all_tool_outputs": true,
    "aggressive_truncation": true,
    "auto_resume": true
  }
}
```

| 옵션                              | 기본값  | 설명                                                                                                                                                                                      |
| --------------------------------- | ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `preemptive_compaction_threshold` | `0.85`  | 선제적 압축을 트리거하는 임계값 백분율 (0.5-0.95). `preemptive-compaction` 훅은 기본 활성화; 이 옵션은 임계값을 커스터마이징합니다.                                                        |
| `truncate_all_tool_outputs`       | `false` | 화이트리스트된 도구(Grep, Glob, LSP, AST-grep)만이 아닌 모든 도구 출력을 잘라냅니다. 도구 출력 트렁케이터는 기본 활성화 - `disabled_hooks`로 비활성화.                                     |
| `aggressive_truncation`           | `false` | 토큰 한계 초과 시, 한계 내에 맞추기 위해 도구 출력을 공격적으로 잘라냅니다. 기본 잘라내기 동작보다 더 공격적. 불충분하면 요약/복원으로 폴백.                                                |
| `auto_resume`                     | `false` | thinking 블록 오류나 thinking 비활성화 위반에서 성공적으로 복구 후 세션을 자동으로 재개. 마지막 사용자 메시지를 추출하고 계속합니다.                                                       |
| `dcp_for_compaction`              | `false` | 압축을 위한 DCP (Dynamic Context Pruning) 활성화 - 토큰 한계 초과 시 먼저 실행. 압축 전에 중복 도구 호출과 오래된 도구 출력을 정리합니다.                                                  |

**경고**: 이 기능들은 실험적이며 예상치 못한 동작을 유발할 수 있습니다. 영향을 이해한 경우에만 활성화하세요.

다른 하네스들이 약속하지만 제공하지 못하는 멀티 모델 오케스트레이션, 안정성, 풍부한 기능을 즐기세요.
계속 테스트하고 업데이트할 것입니다. 저는 이 프로젝트의 가장 집착하는 사용자입니다.
- 어떤 모델이 가장 날카로운 논리를 가졌나요?
- 디버깅의 신은 누구인가요?
- 누가 가장 좋은 글을 쓰나요?
- 누가 프론트엔드를 지배하나요?
- 누가 백엔드를 장악하나요?
- 일상 사용에 가장 빠른 모델은 무엇인가요?
- 다른 하네스들이 어떤 새 기능을 출시하나요?

이 플러그인은 그 경험의 정수입니다. 그냥 최고만 가져가세요. 더 좋은 아이디어가 있으면? PR 환영합니다.

**에이전트 하네스 선택 고민 그만하세요.**
**제가 조사하고, 최고에서 빌려오고, 여기에 업데이트를 배포할 것입니다.**

오만하게 들리고 더 좋은 답이 있다면, 기여해주세요. 환영합니다.

여기서 언급된 어떤 프로젝트나 모델과도 제휴 관계가 없습니다. 이것은 순전히 개인적인 실험과 선호입니다.

이 프로젝트의 99%는 OpenCode를 사용해서 만들어졌습니다. 기능성을 테스트했지만—제대로 된 TypeScript 작성법은 잘 모릅니다. **하지만 이 문서는 직접 검토하고 대부분 다시 썼으니, 자신 있게 읽으세요.**

## 주의사항

- 생산성이 너무 급격히 오를 수 있습니다. 동료가 눈치채지 않게 하세요.
  - 사실, 소문을 퍼뜨릴 겁니다. 누가 이기나 보죠.

    - 재밌는 사실: 그 PR은 OhMyOpenCode의 Librarian, Explore, Oracle 설정 덕분에 발견되고 수정되었습니다.
