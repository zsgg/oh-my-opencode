# 마크다운 문서 한국어 번역

마크다운 문서 파일(.md)을 한국어(.ko.md)로 번역합니다.

## 사용법

`/translate-docs-ko [경로]`

- `$ARGUMENTS`에 경로가 지정되면 해당 파일 또는 디렉토리만 번역
- 경로가 없으면 프로젝트 전체의 `.md` 파일 번역

## 실행 순서

1. **파일 검색**:
   - 지정된 경로 또는 프로젝트 전체에서 `.md` 파일 검색
   - **제외 대상**:
     - `.ko.md`로 끝나는 파일 (이미 번역된 파일)
     - dot(.)으로 시작하는 디렉토리 (`.git`, `.claude`, `.github`, `.opencode` 등)
     - `node_modules`, `dist`, `build` 등 빌드 출력 디렉토리

2. **비교 및 스킵**:
   - 해당 `.ko.md` 파일이 이미 존재하면 원본 `.md` 파일이 번역 이후 변경되었는지 확인
   - 원본이 변경되었거나 `.ko.md` 파일이 없는 경우에만 번역 수행

3. **번역 수행**:
   - 대상 `.md` 파일의 내용 읽기
   - 아래 **번역 규칙**을 엄격히 준수하여 한국어로 번역
   - 동일 디렉토리에 `<원본-이름>.ko.md` 파일로 생성

4. **번역 규칙**:
   - **번역할 것**:
     - 일반 설명, 개요, 요약
     - 지침 및 단계별 가이드
     - 마크다운 테이블의 "설명", "Description", "Notes" 컬럼
     - 주석, 가이드라인, 경고문
   - **영문 유지 (번역하지 않을 것)**:
     - **코드**: 모든 코드 블록 (```...```), 인라인 코드 (`code`), 기술 구문
     - **경로**: 파일 경로, 디렉토리명, URL
     - **식별자**: 변수명, 함수명, 클래스명, 타입명
     - **명령어**: CLI 명령어 및 인자 (예: `git log`, `bun run build`, `gh pr create`)
     - **기술 용어**: LSP, API, Grep, Git, AST, MCP, JSON, CLI, npm, yarn, bun 등
     - **특정 값**: 모델명 (예: Claude 3.5 Sonnet), 도구명 (예: `read`, `edit`), 기술 상수
   - **어조 및 스타일**:
     - 자연스럽고 전문적인 기술 한국어 사용 (기계 번역체 금지)
     - 일관된 전문적 어조 유지
     - 기술적 정확성과 원문의 정확한 의미 보존
     - 원본에 없는 내용, 의견, 인사말 **추가 금지**

5. **서식 유지**:
   - 모든 마크다운 구문 그대로 유지 (헤더, 리스트, 테이블, 인용문, 링크, 볼드/이탤릭)
   - 문서 내 상대 링크가 정상 작동하도록 유지

## 검증 체크리스트

번역 완료 후 결과 검증:
- [ ] `.ko.md` 파일이 원본과 동일한 디렉토리에 생성되었는가?
- [ ] 코드 블록과 기술 명령어가 영문으로 유지되었는가?
- [ ] 파일 경로와 기술 용어(LSP, API 등)가 변경되지 않았는가?
- [ ] 한국어가 자연스럽고 전문적인가? (기계 번역체 아닌가?)
- [ ] 구조와 내용이 원본과 정확히 일치하는가? (추가/누락 없음)
- [ ] 마크다운 테이블과 서식이 그대로 유지되었는가?

## 예시

**원본 (example.md):**
```markdown
# Setup Guide
Use the `lsp_hover` tool to see type info.
1. Run `bun install`
2. Check `src/config.ts`
```

**결과 (example.ko.md):**
```markdown
# 설정 가이드
`lsp_hover` 도구를 사용하여 타입 정보를 확인합니다.
1. `bun install` 실행
2. `src/config.ts` 확인
```
